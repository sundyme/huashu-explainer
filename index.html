它不"生成"视频，
它一帧一帧地画视频。

这个 skill 让 AI 像一间动画工作室那样干活：先写稿、定风格，再用代码把每一帧画出来，最后交给独立的"审片员"挑错。右边这个画面就是用同样的原理实时画出来的，拖动滑块试试。

4 · 核心原理

一帧画面是怎么诞生的

视频就是一秒钟连续放 30 张图。这个 skill 的做法是：写一个函数，你给它一个时刻 t，它就画出那一刻的那张图。要做一条 5 分钟的片子，就把 t 从 0 秒一路喂到 300 秒，每隔 1/30 秒拍一张，一共 9000 张，再拼起来。

下面是一个缩小版的引擎：两个段落，中间有 0.8 秒转场。拖动时间，右侧会显示引擎在这一刻做的每一步计算。拖到 4.0 到 4.8 秒之间，能看到新旧两段同时被画进两块"离屏画布"，再叠在一起。

引擎这一刻在算什么

两块离屏画布

转场时，引擎先把两段各自完整画一遍，再按转场规则混合：fadeShift 的规则是旧画面淡出并往左滑，新画面从右边淡入。skill 内置 13 种这样的转场。

// 一个场景就是一个对象，只有一个 draw 方法
SCENES['s02'] = {
  draw(c, lt, t) {            // c=画布  lt=本段内的时间  t=全片时间
    const p = MO.smooth(FX.p(lt, FX.L('s02', 3), 1.2));  // 第 3 句开口时开始，1.2 秒内完成
    KK.needle(c, theta(lt), p);  // 画针。同一个 lt 永远画出同一张图
  }
};
5 · 窄桥规则之一

为什么"随机"也必须可重复

画星空、粒子、粉笔抖动都要用到随机数。普通随机数每次都不一样，于是同一秒渲两次会得到两张不同的图：改了一处小地方重渲，别处的星星也跟着乱跳，前后对比和局部重渲都没法做。

skill 的规定是所有随机都要用种子。种子像一本写好的随机数表，从同一页开始翻，翻出来的数永远相同。点"再渲一次"对比两种做法。

skill 自带的质检脚本 qa.py 第一项就查这个：同一帧冷启动渲一次、热启动再渲一次，逐像素比对，必须完全一致。

6 · 为什么动起来"顺"

缓动：起步和刹车都要温柔

东西从 A 移到 B，如果全程匀速，起点和终点会显得很生硬，像被线拽着走。3Blue1Brown 的动画用一条叫 smooth 的曲线控制进度：开头慢慢加速，中间快，结尾慢慢停稳。

公式是 6t⁵ − 15t⁴ + 10t³。不用记住它，只要看右边两个点的区别：上面的匀速，下面的用了 smooth。skill 的语法卡把这个公式直接写成了参数，所以每个动作都自动带上这种手感。

7 · 这次实战的关键做法

画面动作挂在"句子"上，不挂在"秒数"上

讲解视频最怕声画不同步：嘴里说"这根针开始转"，画面早转完了或者还没动。常见写法是记下秒数，比如"2.2 秒时让针转起来"。可是配音语速一改，或者稿子里插进一句话，所有秒数都错位，只能手工重调。

这次的做法是先逐句配音，量出每句话的真实长度，再让画面动作挂在句子编号上：FX.L('s02', 2) 的意思是"第 2 句开口的那一刻"。下面调语速或插一句，看两种写法谁会跑偏。

×1.00
口播（示例句子，每块宽度＝这句话说多久）
"针开始转"这个动作，两种写法落在哪

// 写死秒数：改语速、改稿都会错位
if (lt > 2.2) spinNeedle();
// 挂句子：timing.js 里存着每句的真实起点，自动跟着走
if (lt > FX.L('s02', 2)) spinNeedle();

每句配音单独合成还有一个好处：某句读错了只需重配那一句。这次 TTS 把人名 "Xiao Ma" 读成了"笑骂"，口播改成"两位合作者"后只重配了那一句，字幕里保留人名，画面全部自动对齐。

8 · 窄桥规则之二

三方向硬门：先看样帧，再开工

整片动工以前，skill 强制要求同一帧画出三种截然不同的风格给人挑。哪怕你一开始就说了"要 3b1b 风格"也不能跳过，这一条叫"硬门"。原因很实际：一条 5 分钟的片子要写几千行绘图代码，做到一半才发现风格不对，代价远高于事先多画两张图。

这次实战的三张样帧画的都是同一个画面：王虹那段的挂谷针。点一下，看当时为什么选它或放弃它。

9 · 为什么效果稳定

把"审美"写成可以照做的参数

"做得像 3b1b 一点"这种要求，AI 每次的理解都不一样。skill 的语法卡把一种风格拆成一组具体数字和规则，照着做就能稳定复现。下面是 3b1b 语法卡里的几条：

维度写成的参数小白版解释
背景#000 纯黑让彩色线条像在夜空里发光，注意力全在图形上
配色manim 原色饱和度 ×1.5视频经过压缩会变灰，提前加饱和，上传后颜色才刚好
缓动6t⁵−15t⁴+10t³起步慢、中间快、结尾稳，见第 6 节
写字先描边，后填色文字像被一笔一笔写出来，而不是突然出现
颜色语义一种颜色只代表一个概念本片：黄＝正在讲的对象，蓝＝结构，青＝第二个对象，红＝矛盾，绿＝成立
接续用形变接上一个画面上一个图形变成下一个图形，观众的视线不用重新找位置
manim 默认色
饱和度 ×1.5 之后（本片实际使用）

"好看"的五层机制

参考手册 02 把一条好片子拆成五层，从下往上叠：

固定骨架全片统一的版式、字体、色彩语义，观众不用每段重新适应
每幕都是活的画任何时候画面都在动：慢推镜头、流动光点、呼吸点，绝不让画面停住
转场说下一段的话转场用下一段风格的标志性元素，而不是千篇一律的淡入淡出
节拍网格动作落在音乐或口播的节拍上，越到高潮切换越快
叙事锚和结尾梗全片有一个反复出现的视觉线索，结尾呼应开头
10 · 窄桥与开阔地

哪些必须照字面做，哪些可以自由发挥

skill 把规则分成两类。"窄桥"是掉下去就出事的地方，必须一字不差地遵守；"开阔地"只给起点，鼓励发挥。这种区分让 AI 在关键处不偷懒，在创意处不僵化。

窄桥：五条硬规矩

画面必须一直在动

静止超过一两秒，观众就会觉得"卡了"。qa.py 会测每帧的运动面积，找出静止的帧对。

本片例子：审片发现人物卡停了约 3 秒，于是加了缓慢推镜。

所有随机都用种子

保证同一帧永远渲出同一张图，才能局部重渲、前后对比。见第 5 节。

三方向硬门，指定风格也不豁免

用户脑中的"3b1b 风格"和 AI 理解的可能不同，三张样帧摆在一起，分歧当场暴露。见第 8 节。

交付前派独立 agent 审片

写代码的 AI 会"脑补"自己想表达的效果，看不出问题。换一个没参与制作的 agent，只看截图和事实，才挑得出错。见第 11 节。

场景用代码画，人物用 AI 生图

几何、图表、文字用代码画最精确、可动；人脸和角色用代码画很难看，交给图像模型生成关键帧，再由代码合成进场景。

开阔地：给起点，不给配额

35 种风格配方、9 张动画语法卡都只是参考起点。没有"必须用满几种转场""每段至少一个图表"这样的配额。

本片就用了 3b1b 语法卡作骨架，自己新增了挂谷针的数值求解、玻尔兹曼小球碰撞、环面纽结等原卡里没有的画法。

参考手册 08 写给风格作者：新风格要写清它的"签名语言"，也就是一眼能认出来的那几个元素。

11 · 交付前

质检两道关：机器量，旁人看

第一道：qa.py 自动检查

能用数字量的问题，交给脚本。

✓确定性同一帧冷渲、热渲各一次，像素必须完全相同
✓耗时每帧渲染多久，提前发现会拖垮整片的慢场景
✓运动面积相邻帧变化了多少像素，太少就是"画面停了"
✓跳变相邻帧变化太大，通常是某个元素闪了一下
✓框景文字被切掉半截、文字叠在一起、压到字幕带、整帧接近空白
✓转场冒烟每个转场跑一遍，确认不报错、不黑屏

第二道：独立 agent 审片

数字量不出来的问题，交给"另一双眼睛"。本片派了两个审片员：一个只查事实，一个只看画面，共审三轮。点下面切换看它们实际挑出的问题。

    12 · 越用越好的原因

    经验回流：每做一条片，skill 就聪明一点

    参考手册 12 规定了一个闭环：项目里踩过的坑、验证有效的做法，要带着证据写回"正面经验"（07 号手册），下一个项目开工时会读到。"带证据"的意思是写清楚在哪个项目、什么现象、怎么验证过，避免把一时的感觉当成规律。

    做片按手册制作，遇到问题当场解决
    记录坑和解法写进项目的 DEVLOG
    验证确认改动确实有效，比如修好后重渲 50 次都不再卡
    写回整理成一条带证据的经验，放进 07-正面经验
    复用下次开工先读经验，同样的坑不再踩
    本次可以写回的两条

    1. render.py 里单线程的本地服务器会被浏览器的预连接堵住，偶发 120 秒超时。改成多线程服务器 ThreadingTCPServer 后消失。

    2. 口播整片里，画面 cue 挂句子编号而不是秒数，改语速、改稿都不用重调画面。

    14 · 客观评价

    它擅长什么，不擅长什么

    擅长

    数学、科学、数据、历史这类可以用图形、图表、文字讲清楚的内容。

    需要精确的画面：公式、坐标、曲线都是算出来的，不会像 AI 生成视频那样把字画歪。

    可以反复修改：改一句话、改一个颜色，重渲那一段就行。

    局限

    写实场景、真人表演做不了，人物只能靠 AI 生帧再合成。

    token 消耗大：一条 5 分钟的片子要几百万有效 token，大量花在读渲染和质检结果上。

    依赖本地环境：需要 Chromium、ffmpeg、Python，第一次用可能要装依赖（本次就补装过一次 Chromium）。

    渲染是逐帧截图，比专业动画软件慢，长片要等。

    可以带走的六条原则

    就算不做视频，这几条思路在别的 AI 工作流里同样适用：

    1. 入口只做路由。总说明保持简短，细节按需查，AI 不会被无关信息淹没。

    2. 把审美写成参数。能写成数字和规则的，就不要只写形容词。

    3. 输出用纯函数生成。同样的输入永远得到同样的结果，才能比较、才能局部修改。

    4. 在最贵的决定前设硬门。花几分钟出样稿，省下返工几小时。

    5. 让旁观者来验收。做的人和审的人分开，审的人只拿成品和事实。

    6. 经验带证据回流。每次做完都让工具本身变好一点。
